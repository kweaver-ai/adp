# Context Loader (Feature 806350) 实现设计文档

## 1. 代码结构总览

核心实现位于 `agent-retrieval/server` 目录下，按照六边形架构组织：

```
agent-retrieval/server/
├── logics/                          # 业务逻辑层
│   ├── knsearch/                    # KnSearch 模块
│   │   ├── knsearch_logic.go        # 检索编排器 (LocalKnSearch)
│   │   ├── concept_retrieval.go     # Schema 召回 (ConceptRetrieval)
│   │   ├── semantic_retrieval.go    # 实例检索 (SemanticRetrieval)
│   │   └── session_cache.go         # 会话缓存 (SessionCache)
│   └── knrerank/                    # KnowledgeRerank 模块
│       └── knowledge_rerank.go      # 重排序器 (KnowledgeReranker)
├── drivenadapters/                  # 外部服务适配器
│   ├── mf_model_api_client.go       # 模型服务客户端 (LLM/Rerank)
│   ├── ontology_manager.go          # Schema 管理服务适配
│   └── ontology_query.go            # 实例查询服务适配
├── interfaces/                      # 接口定义
│   ├── kn_search.go                 # KnSearch 相关接口和结构
│   └── kn_rerank.go                 # KnowledgeRerank 相关接口
└── infra/config/                    # 配置管理
    └── config.go                    # 配置结构定义
```

## 2. KnSearch 模块实现

### 2.1 核心类: LocalKnSearch

**文件**: `logics/knsearch/knsearch_logic.go`

**职责**: 检索流程的总编排器，协调各子组件完成 6 步检索流程。

```go
// LocalKnSearch 本地KnSearch逻辑实现
type LocalKnSearch struct {
    logger            interfaces.Logger
    mfModelClient     interfaces.DrivenMFModelAPIClient  // 模型服务客户端
    ontologyQuery     interfaces.DrivenOntologyQuery     // 实例查询适配器
    ontologyManager   interfaces.OntologyManagerAccess   // Schema 管理适配器
    sessionCache      *SessionCache                      // 会话缓存
    conceptRetrieval  *ConceptRetrieval                  // Schema 召回组件
    semanticRetrieval *SemanticRetrieval                 // 实例检索组件
    knowledgeReranker *knrerank.KnowledgeReranker        // 重排序组件 (复用)
}
```

### 2.2 Schema 召回: ConceptRetrieval

**文件**: `logics/knsearch/concept_retrieval.go`

### 2.3 实例检索: SemanticRetrieval

**文件**: `logics/knsearch/semantic_retrieval.go`

### 2.4 会话缓存: SessionCache

**文件**: `logics/knsearch/session_cache.go`

## 3. KnowledgeRerank 模块实现

### 3.1 核心类: KnowledgeReranker

**文件**: `logics/knrerank/knowledge_rerank.go`

**职责**: 对概念列表进行重排序，支持 LLM 模式和 Vector 模式，采用单例模式实现。

### 4.1 MF Model API 服务

**服务说明**: 统一的模型服务，提供 LLM 对话和向量重排序两类能力。

**适配器文件**: `drivenadapters/mf_model_api_client.go`

**Base URL 构建规则**:
```

```

#### 4.1.2 Chat Completion 接口 (LLM 对话)

用于 Schema 召回和 LLM 模式的 Rerank。

| 项目 | 内容 |
|-----|------|
| **URI** | `/v1/chat/completions` |
| **Method** | `POST` |
| **Content-Type** | `application/json` |

**请求体 (Request Body)**:

```json
{
    "model": "Tome-pro",
    "messages": [
        {"role": "system", "content": "你是一个智能关系类型筛选助手..."},
        {"role": "user", "content": "请分析以下关系类型..."}
    ],
    "stream": false,
    "temperature": 0.0,
    "top_k": 2,
    "top_p": 0.5,
    "frequency_penalty": 0.5,
    "presence_penalty": 0.5,
    "max_tokens": 5000
}
```

**请求参数说明**:

| 参数 | 类型 | 必填 | 说明 | 配置来源 |
|-----|------|-----|------|---------|
| `model` | string | 是 | 模型名称 | `rerank_llm.model` |
| `messages` | array | 是 | 对话消息列表 | 代码构建 |
| `stream` | bool | 是 | 是否流式 (固定 false) | 硬编码 |
| `temperature` | float | 否 | 生成随机性 (0~1) | `rerank_llm.temperature` |
| `top_k` | int | 否 | 采样范围 | `rerank_llm.top_k` |
| `top_p` | float | 否 | 核采样阈值 | `rerank_llm.top_p` |
| `frequency_penalty` | float | 否 | 频率惩罚 | `rerank_llm.frequency_penalty` |
| `presence_penalty` | float | 否 | 存在惩罚 | `rerank_llm.presence_penalty` |
| `max_tokens` | int | 否 | 最大输出 Token | `rerank_llm.max_tokens` |

**响应体 (Response Body)**:

```json
{
    "choices": [
        {
            "message": {
                "content": "[1, 3, 5]"
            }
        }
    ]
}
```

#### 4.1.3 Rerank 接口 (向量重排序)

用于实例检索阶段的候选重排序。

| 项目 | 内容 |
|-----|------|
| **URI** | `/v1/small-model/reranker` |
| **Method** | `POST` |
| **Content-Type** | `application/json` |

**请求体 (Request Body)**:

```json
{
    "query": "北京餐饮连锁企业",
    "documents": [
        "海底捞火锅连锁",
        "星巴克咖啡",
        "麦当劳快餐"
    ],
    "model": "reranker"
}
```

**请求参数说明**:

| 参数 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| `query` | string | 是 | 用户查询语句 |
| `documents` | array[string] | 是 | 待排序的文档列表 |
| `model` | string | 是 | 固定值 `"reranker"` |

**响应体 (Response Body)**:

```json
{
    "results": [
        {"index": 0, "relevance_score": 0.95},
        {"index": 2, "relevance_score": 0.72},
        {"index": 1, "relevance_score": 0.31}
    ]
}
```

**响应字段说明**:

| 字段 | 类型 | 说明 |
|-----|------|------|
| `results[].index` | int | 原始文档索引 (0-based) |
| `results[].relevance_score` | float | 相关性分数 (0.0~1.0) |

## 6. 接口定义

### 6.1 KnSearch 请求/响应

```go
// KnSearchReq 检索请求
type KnSearchReq struct {
    KnID            string  `json:"kn_id"`             // 知识网络 ID
    Query           string  `json:"query"`             // 查询语句
    SessionID       *string `json:"session_id"`        // 会话 ID (用于缓存)

    XAccountID      string  // 账号 ID (Header 透传)

// KnSearchResp 检索响应

    ObjectTypes   []interface{} `json:"object_types"`   // 对象类型列表
    RelationTypes []interface{} `json:"relation_types"` // 关系类型列表

```

### 6.2 KnowledgeRerank 请求/响应

```go
// KnowledgeRerankReq 重排序请求
type KnowledgeRerankReq struct {
    QueryUnderstanding *QueryUnderstanding    `json:"query_understanding"` // 查询理解结果
```

## 7. 错误处理与降级策略

| 场景 | 组件 | 降级策略 |
|-----|------|---------|
| Session Cache 失败 | LocalKnSearch | 跳过缓存，继续执行后续流程 |
| Schema 召回 LLM 失败 | ConceptRetrieval | 返回前 TopK 个关系类型 |
| Schema 精排 LLM 失败 | LocalKnSearch | 跳过精排，使用召回结果 |
| 单个实例查询失败 | SemanticRetrieval | 跳过该查询，继续其他并发任务 |
| Vector Rerank 失败 | SemanticRetrieval | 返回原始候选列表（不排序） |
| LLM 批次处理失败 | KnowledgeReranker | 跳过该批次，继续其他批次 |
| 概念格式化失败 | KnowledgeReranker | 使用概念名称作为文本 |
